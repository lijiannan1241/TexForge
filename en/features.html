Batch actions (113)

Size and canvas: resize, crop, rotate, flip, padding, canvas expansion, anchor alignment. Settle geometry first so the cost of later steps is predictable.

Quality and format: resampling, sharpening, quantization, bit depth, PNG / JPEG / WebP / TGA / DDS conversion and compression to a target file size.

Content: watermarks, borders, rounded corners, masks, color adjustments and ICC color space conversion.

Files and metadata: batch renaming, folder planning, EXIF / XMP / IPTC reading, writing and stripping.

Execution model: actions run in sequence, each output feeding the next. One failure does not stop the batch; failed items land in the report so you retry only those.

Read more：Batch image processing in practice: configure once, process thousands →

Texture atlas packing (69 formats)

Layout: by size, by name or by group, with padding, edge extrusion, rotation and trimming to alpha bounds.

Output: Unity, Godot, Unreal, Cocos2d, Phaser 2/3, PixiJS, Spine, LibGDX, SpriteKit, Starling, Egret, LayaAir, WeChat mini games, plus generic JSON / XML / plist / CSS / CSV.

Validation: POT / NPOT, max size, padding consistency and empty-region checks before export.

The descriptor is written next to the atlas image with a matching name, so the engine picks it up with no hand-edited coordinates.

Read more：A complete guide to texture atlas packing: padding, trimming, POT and 69 formats →

Engine data export (24 formats)

Folder planning for Unity, Unreal, Godot, Cocos and custom templates, written into the paths each engine expects.

JSON, XML, plist, CSS, CSV, sprite sheets and engine-specific metadata in a single run.

Custom templates fit in-house engines and internal conventions, with trimmable fields and nesting.

One atlas can be exported to several engine targets in parallel instead of being repacked per platform.

Read more：24 engine data formats: export for Unity, Godot, Unreal and Cocos at once →

Normal maps and channel packing

Generate normal maps from height maps with adjustable strength and a Y-axis switch for OpenGL or DirectX conventions.

Pack roughness, metallic and AO into RGB channels using ORM / RMA conventions instead of manual channel work.

Configurable channel order to match Unity and Unreal habits.

Normal maps are always treated as linear data, so an sRGB pipeline cannot double-correct them.

Read more：Normal maps and channel packing: doing ORM, roughness and metallic right →

Mipmaps and platform size limits

Build power-of-two mip chains with selectable resampling filters and alpha handling.

Built-in size-limit validation for mobile and desktop targets; oversized textures are flagged before export, not after an engine error.

Useful when shipping several platform builds from one source set: one set of sources, several target specs.

Read more：Mipmaps and platform size limits: stop tripping on mobile textures →

Sprite slicing and nine-patch

Split a sprite sheet by grid or transparent gutters into individual images with sequenced names.

Nine-patch slicing separates corners and edges by border pixels for stretchable UI.

Sliced output can go straight into batch actions or into the atlas packer.

Read more：Sprite sheets and nine-patch: slicing mobile UI the right way →

Metadata and naming conventions

Read, write and strip EXIF / XMP / IPTC, including batched edits to description, author and copyright fields.

Renaming supports prefixes, suffixes, sequence numbers, original-name variables and folder planning.

Strip private fields before publishing and write back copyright and source information in the same run.

Read more：EXIF / XMP / IPTC workflows: copyright, authorship and bulk cleanup →

Asset audits and reports

Scan naming conventions, dimension consistency, duplicates and missing normal / color pairs.

Export CSV / JSON reports for CI gates, art reviews or release records.

Batch evaluation against platform specs such as mobile POT limits.

Reports and presets can live in version control as part of the asset specification.
