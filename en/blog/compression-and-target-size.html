Compression and target size: balancing quality against package size

Target-size compression, PNG optimization, lossy versus lossless trade-offs, and verifying results in bulk instead of eyeballing every file.

Compression2026-10-28·3 min read

Key takeaways

  • Set a size budget before choosing a strategy
  • PNG optimization is usually lossless and reliably useful
  • Verify compression with metrics, not eyeballing

Download size is the first barrier for players and a hard limit for many stores. Images usually dominate a build, but “how small” cannot be a feeling — it needs a budget.

Budget first, compression second

A workable flow: set the installer ceiling, subtract code, audio and data, and what remains is the image budget. Split it by asset type — UI, characters, environments, effects. With a budget, compression has a target.

Without a budget, compression becomes a tug of war: artists say it looks blurry, engineers say it is still too big. Numbers make the discussion concrete.

PNG optimization

PNG is lossless; gains come from better filtering, palettes and compression parameters. For UI, icons and pixel art that need exact edges, PNG optimization is usually the first choice because pixels do not change.

For photographic or gradient-heavy textures, lossy formats such as JPEG and WebP shrink files substantially, but watch for banding and edge artifacts, especially with alpha.

Target-size compression

Some channels cap individual image or package size. That calls for target-size compression: given a ceiling, the tool iterates quality settings to approach but not exceed it.

This iteration must be automated. Manual parameter tuning is slow, irreproducible and rarely consistent across a batch.

  • Set a ceiling and a tolerance so you are not recompressing for a few kilobytes.
  • Record the actual quality parameters per file for traceability.
  • Report images that cannot meet the target instead of failing silently.

How to verify

Do not stop at “it opens”. Check three things: whether the size meets the target, whether dimensions and channels are correct, and whether key regions show visible damage. In bulk, use a metric such as structural similarity to shortlist suspicious files, then review those manually.

The acceptance test for compression is “no visible difference on the target device”, not “a smaller file”.

Takeaway

Compression is budget, strategy and verification. The budget sets the goal, the strategy picks the method, verification decides whether you can ship. Making it a batch keeps it stable across releases.
