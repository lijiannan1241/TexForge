Batch image processing in practice: configure once, process thousands

How to combine TexForge's 113 batch actions into a stable asset pipeline, from action sequences and presets to retrying failed items.

Batch processing2026-09-02·3 min read

Key takeaways

  • Actions stack in order; one failure does not stop the batch
  • Presets are the smallest reusable unit for a team
  • Result reports make retries precise

Art assets are rarely just a few files. One character can have a dozen animations, several skins and multiple resolution tiers; one UI set can contain hundreds of slices; a single release may require re-exporting every texture. Opening, resizing, saving and renaming by hand is slow and easy to get wrong.

Why it pays to get it right once

The real value of batch processing is not speed — it is consistency. When dimensions, naming, compression and metadata all come from one configuration, assets become reproducible: another person, another machine, or the same machine three months later produces the same result.

TexForge turns that configuration into an action sequence stored in a preset. Presets travel with the project and can live in version control as part of the asset spec.

How the 113 actions combine

Actions run in the order you add them; the output of one becomes the input of the next. A practical order is geometry first, then color and quality, then format and metadata.

  • Geometry: resize, crop, rotate, flip, canvas expansion, padding. Fix dimensions first so later steps have predictable costs.
  • Quality: resampling, sharpening, quantization, compression. Sharpen after resizing, or downscaling will erase the detail you added.
  • Format: target format such as PNG, JPEG or WebP, plus bit depth and alpha.
  • Metadata: renaming, folder structure, EXIF / XMP / IPTC writing or stripping.

Presets turn configuration into an asset

Save the sequence as a preset. From then on, one click in the GUI or one flag on the command line reuses the same logic. Teams usually split presets by purpose: icons, character art, UI slices, store images.

A preset is good enough when you can hand it to someone else and they produce an identical folder structure and identical files without asking you anything.

Failures and retries

The worst batch run is the one that dies halfway with no record of what was skipped. TexForge keeps going when a single file fails, records the item and the reason in the report, and lets you retry just those items after fixing the source.

Three practical steps

  1. Pick 5 to 10 representative images, run the preset, and check dimensions, naming, file size and visual quality.
  2. Run the full batch, watch duration and failures, and confirm there is enough disk space.
  3. Archive the report and commit it with the preset so this asset release is documented.

Takeaway

Batch processing is not a one-off convenience; it turns asset production into a repeatable engineering process. The action sequence provides correctness, the preset provides consistency, and the report provides traceability.
