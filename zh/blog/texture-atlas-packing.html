纹理图集打包完全指南：留白、裁剪、2 的幂与 69 种格式

图集不只是把小图拼成大图。留白、边缘扩展、裁剪、旋转与格式选择，决定了运行时的采样质量与内存占用。

纹理图集2026-09-09·3 分钟阅读

核心要点

  • 留白与边缘扩展解决采样溢色
  • 裁剪省空间，但必须同步更新描述文件
  • 格式选择要跟引擎和平台走，而不是随手选

把一百张小图拼进一张大图，听起来只是排列组合。但真正上线后出现的问题，往往不是「拼不进去」，而是边缘出现杂色、图集尺寸超出平台上限、描述文件里坐标对不上。

留白与边缘扩展

GPU 采样时会对相邻像素做插值。当两个精灵紧贴在一起，采样器可能把邻居的颜色混进来，表现为边缘出现一圈异色。留白（padding）在精灵之间插入透明像素，边缘扩展（extrude）则把精灵最外一圈像素向外复制，进一步降低溢色风险。

经验值：普通 2D 精灵留 2 到 4 像素；使用线性过滤、缩放比例不固定的项目可以更大。图集本身还需要在四周留边，避免贴图边界被 clamp 采样影响。

裁剪：省空间，但要同步元数据

很多精灵有大量透明区域，按 alpha 边界裁剪后再记录原始偏移，可以显著提升图集利用率。代价是描述文件必须携带原始尺寸与偏移量，否则运行时定位会错位。

TexForge 在导出时把裁剪信息写入对应的引擎描述文件，Unity、Godot、Unreal 等格式都保留了原始矩形与偏移字段。如果手写导出脚本，最容易漏掉的正是这一步。

2 的幂与平台上限

部分老设备与压缩格式要求纹理边长为 2 的幂（POT）。现代 GPU 多数支持 NPOT，但移动端压缩纹理、Mipmap 生成仍常与 POT 绑定。打包前应确认目标平台的限制，并把校验前移到导出阶段，而不是等引擎报错。

  • 确认最大边长：移动端常见 2048 或 4096，桌面端可更高。
  • 确认是否必须 POT：需要 ET C2 / ASTC 等压缩格式时尤其注意。
  • 确认 Mipmap：开启后图集尺寸会向上取整，留白也要相应调整。

69 种格式怎么选

格式选择取决于运行时，而不是个人偏好。Unity 用自有描述文件；Godot 有 3.x 与 4.x 的差异；Unreal 走它自己的 sprite 数据；Web 端常见 JSON Hash / Array、Phaser、PixiJS、CSS、Spine；小游戏平台还有各自的约定。

TexForge 同时导出图集图片与描述文件，命名与目录保持一致，复制进项目即可被引擎识别。需要适配自研引擎时，可以用自定义模板裁剪字段。

导出前检查清单

  1. 图集尺寸是否在平台上限内，是否需要 POT。
  2. 留白是否足够，四周是否有边距。
  3. 裁剪后的偏移是否已写入描述文件。
  4. 描述文件中的图片路径与实际文件名是否一致。
  5. 在引擎里实际导入一次，确认没有错位或模糊。

小结

好的图集不是「塞得最满」的那张，而是「在目标平台上不出问题」的那张。留白、裁剪、POT 与格式，每一项都对应一个真实的运行时约束。把这些约束固化进打包配置，比事后逐张排查便宜得多。
