法线贴图与通道打包：ORM、粗糙度、金属度的正确做法

从高度图生成法线贴图，到 ORM / RMA 通道打包与 Y 轴方向差异，梳理最常见的颜色空间与通道顺序陷阱。

法线贴图2026-09-23·3 分钟阅读

核心要点

  • 法线贴图必须按线性数据对待
  • Unity 与 Unreal 的通道约定不同
  • Y 轴方向错了，光照会整体反掉

法线贴图看起来只是「一张偏蓝的图」，但它承载的是向量数据，不是颜色。把它当普通贴图处理，最常见的结果是光照方向怪异、边缘发灰、压缩后出现色带。

法线贴图是数据，不是颜色

法线贴图的 RGB 分别编码 X、Y、Z 方向，取值范围映射到 0 到 1。因此它必须按线性空间处理：不要做 sRGB 转换，不要用针对照片的压缩参数，也不要随手调色。

从高度图生成时，强度参数决定凹凸的夸张程度。太强会让细节互相穿插，太弱则在大光源下几乎看不出来。建议在引擎实际光照下调整，而不是只看平面预览。

Y 轴：OpenGL 与 DirectX

不同图形 API 对绿色通道的方向约定不同。OpenGL 习惯 Y 向上，DirectX 习惯 Y 向下。方向搞反，模型的光照会整体翻转，表现为「凹凸看起来是凹的」。

Unity 与 Unreal 的默认约定不同，跨引擎复用法线贴图时必须确认这一点。TexForge 在生成法线贴图时提供 Y 轴翻转开关，避免导出后再用图像工具手工反转绿色通道。

通道打包：ORM 与 RMA

为了减少贴图数量，美术常把环境光遮蔽（AO）、粗糙度（Roughness）、金属度（Metallic）打包进一张图的三个通道。常见约定有两种：

  • ORM：R = AO，G = Roughness，B = Metallic，常见于 Unreal 工作流。
  • RMA：R = Roughness，G = Metallic，B = AO，部分团队与管线使用。
  • Unity 的 HDRP / URP 又有自己的遮蔽与光滑度习惯，光滑度常是粗糙度的补值。

通道顺序错一位，材质看起来就完全不对：金属区域变成粗糙，缝隙的遮蔽跑到高光上。批量打包的价值在于，通道映射只配置一次，之后每张图都按同一规则生成。

常见陷阱

  1. 把法线贴图存成 sRGB，导致引擎再次做伽马转换。
  2. 用 JPEG 存法线贴图，压缩噪点直接变成错误的法线方向。
  3. 打包时忘记 AO 需要单独烘焙，直接用灰度图凑数。
  4. 粗糙度与光滑度混用，没有做 1 减 的反转。
  5. 不同平台用同一套通道顺序，忽略了引擎差异。

把这些固化进批处理

通道映射、Y 轴方向、色彩空间标记，都是「一旦定下就不该每次重想」的参数。把它们写进预设，和尺寸、格式一起批处理，才是稳定的做法。

小结

法线贴图与通道打包的难点不在工具，而在约定。确认引擎、确认色彩空间、确认通道顺序，再用批处理保证每次都一致，材质问题会少一大半。
