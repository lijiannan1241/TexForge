精灵表与九宫格：移动 UI 切图的正确姿势

精灵拆分、九宫格拉伸区定义、边框与圆角的批处理，以及导出后如何在引擎里验证不变形。

精灵与 UI2026-10-14·3 分钟阅读

核心要点

  • 九宫格的关键是四条分割线
  • 圆角与描边必须放在不可拉伸区
  • 切图后要在真实分辨率下验证

移动端 UI 大量使用可拉伸面板：按钮、对话框、气泡、列表项。它们的共同点是「同样是圆角矩形，但宽高千变万化」。如果每种尺寸都切一张图，包体会迅速膨胀。

九宫格的原理

九宫格把一张图用两条水平线、两条垂直线分成九块。四个角保持原样，四条边单向拉伸，中间双向拉伸。这样一张小图就能适配任意尺寸，同时保持圆角与描边不变形。

关键在分割线的位置：线必须放在「可以安全拉伸」的区域。圆角、描边、装饰元素都要落在角块或边块的非拉伸部分，否则一拉就糊。

精灵拆分

反向的需求同样常见：拿到一张合并的精灵表，需要拆成单图，或者重新按新规则打包。拆分时要处理不规则间距、透明边距与命名，手工做既慢又容易错位。

TexForge 的图集工具箱提供拆分与校验能力，可以按透明边界识别精灵、输出单图并保持命名规则，方便二次加工或迁移到新图集。

批处理圆角与描边

UI 资源常有统一规范：圆角半径、描边宽度、内边距、投影。把这些做成批处理动作，比让每个美术各自发挥更可控。改规范时只需改一次预设，全量重出。

  • 圆角半径与描边宽度用参数控制，避免手工像素级调整。
  • 输出保留透明边距，给九宫格分割线留出空间。
  • 同时导出 @1x / @2x / @3x，命名规则统一。

导出后的验证

九宫格最容易出错的地方不是切图，而是「在引擎里被拉变形」。导出后应在真实分辨率与极端宽高比下各看一次：超长按钮、超窄列表项、超大气泡。

在 320 像素宽和 1440 像素宽下都正常的九宫格，才算真的做完。

小结

精灵表解决「多」，九宫格解决「变」。前者靠打包与拆分工具，后者靠分割线规范与验证。两者都适合批处理，因为它们本质上都是规则问题。
